# Entities

This application will use entities to model `groups`. `Groups` are the core organizational unit for the `cli` project and how artifacts are published to the repository.

## Definition

The FusionAuth `kickstart` needs to be updated to create the configuration for `groups`. We need to create an `EntityType` called `Group` and it needs these permissions:

* `owner`
* `contributor`

The `owner` permissions allows the user to add and remove members from the group. The `owner` permission also allows the user to publish artifacts to the group.

The `contributor` permissions allows the user to publish artifacts to the group.

Each group will then be modeled as an `Entity` of the type `Group`.

The name of the `group` will be stored on the `Entity` using the `clientId` field. Groups generally use reverse domain notation to avoid conflicts with other names. However, this is not a strict requirement and `groups` can have simple names such as `my-cool-group`. 

## State

The state of a `group` will be stored on a custom data field on the Entity. This field will be called `state` and it will have these values:

* `verified` - The group is active and has been verified if required
* `pending` - The group is pending verification
* `failed` - The group has failed verification

The state of a user's membership in a `group` is stored on a custom data field on the `EntityGrant`. This field is called `state` and it will have these values:

* `active` - The user is a member of the group
* `pending` - The user has been invited to the group but has not yet accepted the invitation
* `declined` - The user has declined the invitation

## Service

We will create a `GroupService` that will handle all the business logic for `groups`. This service will be responsible for retrieving groups, creating groups, and adding and removing members from groups. This service will use the FusionAuth Java Client Library to interact with the FusionAuth API.

The `ViewService` will be updated to leverage the `GroupService` to retrieve the list of groups.

## Listing Groups

The list of `Groups` on the sidebar navigation and the `group` list page are determined by calling the FusionAuth `GET /api/entity/grant/search?userId={uuid}` API. This API returns all the entities that a user has been granted permissions to.

The `state` of the `Entity` will be used to display the icon on the sidebar and the `active` column on the listing page.
